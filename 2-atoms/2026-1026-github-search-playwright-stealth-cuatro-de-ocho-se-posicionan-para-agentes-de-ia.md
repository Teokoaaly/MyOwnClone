## Claim
**Cuatro de los ocho repositorios legibles se posicionan explícitamente para agentes de IA**, y lo hacen en su campo `description` y en sus topics, no en el README: `jo-inc/camofox-browser` (*"Stealth headless browser **for AI agents** — bypass Cloudflare, bot detection, and anti-scraping. Drop-in Puppeteer/Playwright replacement"*, topic `ai-agent`); `seleniumbase/SeleniumBase` (*"CDP Mode launches a stealth browser that bypasses bot-detection/CAPTCHAs. Adds stealth to Playwright and **has an MCP server for AI agents**"*, topics `playwright`, `bot-detection`); `acunningham-ship-it/veilbrowser` (*"Stealth browser for AI agents — real Chrome over raw CDP, **no Playwright/Puppeteer**. TypeScript + **MCP-native**. Passes sannysoft 57/57, bypasses Cloudflare"*, topics `ai-agents`, `mcp`, `cdp`, `chrome-devtools-protocol`); y `greekr4/playwright-bot-bypass`, cuya descripción entera es *"Claude Code skill to bypass bot detection (Google CAPTCHA, etc.)"*, con topic `claude-code-skill`, 205 estrellas, 16 forks, JavaScript, MIT, 3.316 KB y **0 issues abiertos**. Los dos últimos son los casos extremos: `veilbrowser` **deja atrás Playwright y Puppeteer** —Chrome real sobre CDP crudo— y `greekr4` **no distribuye código de evasión sino una skill para Claude Code**.

## Why It Matters
Este es el mismo movimiento que el vault ya registró en el lado comercial —2Captcha publicando cuatro servidores MCP y su Browser API y Web Unlocker ([[2026-1024-2captcha-giro-hacia-scraping-y-mcp-para-agentes]]), CapSolver pasándose a ser capa de automatización para agentes ([[2026-1026-capsolver-mcp-y-agentes-como-primera-superficie-comercial]]), y la taxonomía de herramientas de seguridad que ya tenía la categoría "agente" como dominante ([[2026-1023-ai-security-tools-mcp-como-superficie-de-ataque]])— **ahora medido en el lado open source**, y con un dato que la parte comercial no tenía: **el canal de distribución de la capacidad está cambiando de API a skill**.
`greekr4/playwright-bot-bypass` es el ejemplo más relevante para el vault: **205 estrellas para un artefacto que es una skill de Claude Code**, no una biblioteca. Es decir, hay demanda medible por evasión anti-bot **empacada como instrucción para un agente**, y ese formato de distribución no aparece en ninguna otra captura del vault —ni en 2Captcha, ni en CapSolver, ni en los relay chinos. Si el producto del vault alguna vez necesita scraping con evasión, tiene un formato de integración nuevo a considerar.
La segunda lectura es de **desplazamiento de la dependencia**: `veilbrowser` usa Chrome real sobre CDP crudo y declara explícitamente **no usar Playwright ni Puppeteer**, y `camofox-browser` se ofrece como **reemplazo drop-in de ambos**. Es decir, la capa de evasión está **dejando de ser un plugin** —que es lo que eran `patchright` y los plugins stealth— y se está convirtiendo en **el navegador entero**. El repositorio `techinz/browsers-benchmark`, con su lista de siete vendors, mide precisamente estos motores entre sí. Para una arquitectura que ya tiene una capa de datos que no depende de Playwright, la conclusión es incómoda pero útil: **el coste de la evasión se ha movido de "añadir un plugin" a "elegir un runtime de navegador"**, que es una decisión de infraestructura y no una dependencia.
