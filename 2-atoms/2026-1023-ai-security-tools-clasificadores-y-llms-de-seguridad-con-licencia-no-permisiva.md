## Claim
Las dos secciones de modelos del listado son pequeñas y con la licencia como eje. **"Prompt-Injection Classifier Models"** tiene **cinco entradas**, todas en Hugging Face, y tres están **gated** o con licencia no permisiva: `Prompt Guard 86M` (Meta, Llama 3.1, "access: gated manual"), `PromptGuard` (CodeIntegrity AI, Apache-2.0 pero "gated auto") y `prompt-injection-sentinel` (Qualifire, "license: other", "gated auto"). Solo dos son francamente abiertos: `Wolf Defender Prompt Injection` (Apache-2.0, open, Safetensors + ONNX) y `DeBERTa v3 Prompt Injection v2` (Apache-2.0, open, Safetensors + ONNX). **"Specialty Security LLMs"** (7 entradas) mezcla modelos con licencia permisiva (`Lily-Cybersecurity-7B-v0.2`, Apache-2.0, open; `Trendyol Cybersecurity LLM v2 70B`, Apache-2.0, open; `Antares-1B`, Apache-2.0 pero "gated manual") con modelos derivados de una base con **Llama 3.1 Community License** (`Foundation-Sec-8B-Reasoning`, que el README matiza: "not an Apache-only model; retain the base-model license and NOTICE obligations"), con restricciones del autor (`WhiteRabbitNeo 2.5`) o **abliterated** (`RavenX CyberAgent 35B`, "built from an abliterated base model", "use only in authorized, sandboxed agent harnesses with tool-call validation"). El README obliga a esta precisión en el formato de la entrada: "license: Apache-2.0 · access: open · artifacts: Safetensors".

## Why It Matters
*tentative* — la inferencia es del lector: **la disponibilidad real de un clasificador de prompt injection está detrás de una puerta de acceso o de una licencia**, lo que convierte la dependencia en una decisión de producto (cuenta, términos, distribución del modelo en el stack) y no en un `pip install`. Para el vault, que ya tiene decisiones de proveedor de embeddings tomadas como deuda irreversible ([[2026-1022-myclone-viaje-embeddings-voyage]]), la lección es preventiva: elegir un clasificador *gated* o con licencia "other" como dependencia de runtime es el mismo error de fijar proveedor antes de indexar, con la dependencia de por medio; y el mismo criterio aplica a la base vectorial, que el vault ya tiene en pgvector con embeddings inferidos ([[2026-1022-pgvector-embeddings-openai-inferidos]]).

El mismo eje aplica al modelo de seguridad especializado: un modelo abliterated o con licencia restrictiva no es una dependencia aceptable para un producto que procesa datos de clientes, aunque su README lo posicione para "autonomous security assessment". Y el propio README marca límites de confianza en las cifras de los modelos: en `Foundation-Sec-8B-Reasoning` advierte que el análisis de seguridad "can hallucinate; this is not a verified scanner or guardrail". El patrón de publicar metadatos de licencia y acceso por entrada es exactamente el que hace falta para que esa decisión sea auditable antes de integrar, y es la misma disciplina de "la fuente se cita, se fecha y se contrasta" que el vault ya aplica a sus propias capturas — el mismo cuidado con el que el listado declara su propia licencia CC0 y sus métricas como snapshots estáticos ([[2026-1023-ai-security-tools-repo-cc0-readme-generado-y-metricas-estaticas]]).
