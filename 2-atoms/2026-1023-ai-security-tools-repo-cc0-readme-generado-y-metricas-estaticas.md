## Claim
El repo `scadastrangelove/awesome-ai-security-tools` es **CC0-1.0** ("the contributors have waived all copyright and related rights to this list … Linked projects retain their own licenses — check each before use"), lo mantiene Sergey Gordeychik, tiene **1.7k stars, 21 watchers, 428 forks, 280 commits, 1 branch y 0 tags**, y su README **no se escribe a mano**: "This README is generated from structured data" (`data/sections.json`, validado por `data/schema.json`, regenerado con `python3 scripts/update_github_metrics.py` + `gen_readme.py --check`). Las estrellas y las fechas del último commit son **snapshots estáticos** ("GitHub-hosted entries show static ★ stars and last-commit snapshots"), con la entrada más reciente refrescada el **2026-10-21**. Las reglas de contribución exigen apuntar al repo canónico (no un fork), verificar la URL, etiquetar el tipo correcto y añadir un flag de licencia para todo lo no permisivo, no comercial o sin licencia.

## Why It Matters
Es un precedente de higiene para el vault, que trabaja con fuentes que no puede editar. Tres cosas: (a) la fuente es auditable —datos estructurados, esquema y generador— y por tanto las cifras que el vault cita de ella son reconstruibles; (b) la postura de licencia muestra el patrón correcto para un catálogo: el índice es libre (CC0) y **cada entrada conserva su licencia**, igual que un producto con superficie legal pública y específica ([[2026-1022-superficie-legal-publica-dpa-clon-terms]]); (c) el README admite openly que sus estrellas son estáticas, lo que matiza cualquier lectura de "popularidad = salud" del proyecto, la misma cautions que el vault ya registró para el proxy de Midjourney ([[2026-1023-midjourney-proxy-popularidad-y-actividad-del-repo]]). El reverso: un producto sin repos públicos [[2026-1022-sin-repos-publicos-github]] no puede ofrecer ni esa auditabilidad ni esa contribuibilidad.
