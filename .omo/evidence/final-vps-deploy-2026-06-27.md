The table existed (alembic head `f3a4b5c6d7e8`) but was empty. A
one-shot Python script aggregated the existing `ai_invocations` rows
and inserted them into `cost_daily_rollup`:

```
Aggregated 1 rollup rows from ai_invocations
  (datetime.date(2026, 6, 26), '00000000-0000-4000-8000-000000000001', 'minimax-m2.7', 'chat', 1, 0, 0, 1, 0)
Inserted 1 new rows, updated 0 existing
Final cost_daily_rollup count: 1
```

The script logic:
1. `SELECT created_at::date, tenant_id, model, task, COUNT(*), SUM(prompt_tokens), SUM(completion_tokens), COUNT(*) FILTER (WHERE success), COUNT(*) FILTER (WHERE NOT success) FROM ai_invocations GROUP BY day, tenant_id, model, task`.
2. For each aggregated row, check if a row already exists in
   `cost_daily_rollup` matching `(tenant_id, day, task, model)` —
   if so, UPDATE, otherwise INSERT.
3. The table has no UNIQUE constraint, so plain INSERT/UPDATE was used
   (ON CONFLICT would have failed: "there is no unique or exclusion
   constraint matching the ON CONFLICT specification").

If the new container has issues, rollback is two steps:

1. **Roll back to the old image** (note: the old image was pruned by
   `docker image prune` during this session. To restore, rebuild from
   commit `8d16d1cc...` which is the M14 source):
   ```bash
   cd /opt/myownclone/worktrees/sisyphus-vps-integration
   sudo -n -u myownclone git checkout 8d16d1cc -- api/controllers/console/myownclone/ai_models.py
   cd ops
   sudo -n docker compose -f docker-compose.backend.prod.yml build api
   sudo -n docker tag ops-api:latest myownclone_api:rollback
   ```

2. **Restart with the old image**:
   ```bash
   sudo -n docker stop myownclone_api
   sudo -n docker rm myownclone_api
   sudo -n docker run -d --name myownclone_api \
       $(cat /tmp/api_env.json | python3 -c '... same flags as recreate ...') \
       myownclone_api:rollback \
       gunicorn --bind 0.0.0.0:5001 --workers 2 --timeout 60 \
                --access-logfile - --error-logfile - \
                api.app_factory:app
   ```

The backup env vars at `/tmp/api_env.json` will be lost on container
recreation. To preserve them long-term, save them to
`/opt/myownclone/shared/api_env.json` (read-only after generation).

## Risks

1. **Image not persisted in registry**: `ops-api:latest` is local to
   this VPS. If the host loses its Docker storage, the fix is lost.
   Future rebuilds from the worktree will produce the same image.
2. **Image prune risk**: `docker image prune` already ran once. If it
   runs again with `--all`, the dangling `ops-api:latest` might be
   removed. Tagging as `myownclone_api:fix-persisted` keeps it pinned.
3. **Env vars backup**: `/tmp/api_env.json` is in the container's
   ephemeral layer. Move it to a durable location if long-term
   preservation matters.
4. **One-time fix**: The fix is in the code, but no automated
   regression test runs in production. The endpoint is healthy and
   returns 200, but token growth or schema drift could regress.
