# Auditoria — i18n Multilenguaje (TASK-360-05)

## Resumen
- **Estado:** Rojo — next-intl v4.13.0 instalado pero completamente desconectado del codigo productivo
- **Riesgo principal:** 0 de 44 paginas usa `useTranslations()`, 63 keys en `en.json` vs cientos de strings hardcodeadas en componentes, sin ruteo por locale
- **Veredicto prod:** No apto para multilenguaje. Requiere reconexion completa de next-intl antes de escalar a 50 idiomas

## Open Questions

1. **Estrategia de ruteo**: `localePrefix: "never"` (solo cookie, facil, sin SEO) o `localePrefix: "as-needed"` (URL prefix, SEO, mas trabajo)? La decision condiciona middleware y routing.
2. **Compatibilidad con middleware actual**: El middleware de next-intl necesita coexistir con el proxy de Flask + tenant detection. Hay que componer ambos middlewares.
3. **Mantenimiento de 50 idiomas**: Se procede con el plan I18N_50_LANGUAGES_PLAN.md? Eso implica script de traduccion auto con OpenAI.
4. **SignOutButton**: Esta en español. Se corrige ahora (quick fix) o se espera a i18n global?
