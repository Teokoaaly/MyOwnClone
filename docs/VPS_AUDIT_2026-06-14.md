## Findings

### P0 - Chat runtime has no LLM provider configured

The public clone endpoint is registered and reachable, but chat fails with:

```text
No LLM API key configured. Set OPENAI_API_KEY, ANTHROPIC_API_KEY, or TOGETHER_API_KEY
```

The active backend environment did not include `OPENAI_API_KEY`,
`ANTHROPIC_API_KEY`, `MINIMAX_API_KEY`, or `TOGETHER_API_KEY`.

Remediation in this branch:

- `api/core/model_manager.py` now supports `OPENAI_BASE_URL`,
  `OPENAI_API_BASE` legacy alias, and `OPENAI_MODEL`.
- `ops/backend.env.production.example` documents OpenAI-compatible provider
  configuration, including DeepSeek.

### P0 - Frontend release env had unreadable permissions

`next start` logged:

```text
EACCES: permission denied, open '/opt/myownclone/releases/20260613070925/MyOwnClone/.env.production'
```

The file was owned by `root:root` with mode `600` while the service runs as
`myownclone`.

Manual server fix applied during audit:

```bash
chown myownclone:myownclone /opt/myownclone/releases/20260613070925/MyOwnClone/.env.production
chmod 600 /opt/myownclone/releases/20260613070925/MyOwnClone/.env.production
systemctl restart myownclone-frontend.service
```

Remediation in this branch:

- `ops/deploy-frontend.sh` now installs `.env.production` from the shared env
***REMOVED***le with owner `myownclone:myownclone` and mode `0600` on each deploy.

### P1 - Email, billing, and webhook secrets are missing

The backend runtime was missing production integration keys for email, billing,
and inbound webhook validation. This means those features will either fail or
stay disabled until configured:

- `RESEND_API_KEY`
- `STRIPE_SECRET_KEY`
- `SENDGRID_INBOUND_WEBHOOK_SECRET`

The SendGrid endpoint rejects inbound email in production when the webhook
secret is missing.

### P1 - Public RAG has no indexed dataset for the demo clone

The backend logged:

```text
No dataset found for clone=demo-clone-001 silo=teach tenant=demo-tenant-001
```

After configuring an LLM key, upload or ingest source content before expecting
grounded answers.

### P2 - `/api/auth/validate-sso` is not implemented

The frontend logs show requests to `/api/auth/validate-sso`. The repository only
defines Auth.js catch-all routes under `src/app/api/auth/[...nextauth]/route.ts`,
so Auth.js treats `validate-sso` as an unknown action and returns `400`.

This is likely an external integration, stale browser request, monitor, or proxy
expectation pointing at a route that is not part of this app.

### P2 - Multiple historical project copies exist on the VPS

The server contains several old checkouts:

- `/root/MyOwnClone`
- `/root/MyOwnClone-new`
- `/root/MyOwnClone_new`
- `/opt/myownclone`

Only `/opt/myownclone/current` appears to be active. Keeping old copies with
legacy remotes and env files increases confusion and secret exposure risk.

## Deployment Notes

To use DeepSeek or another OpenAI-compatible provider:

```bash
OPENAI_API_KEY=...
OPENAI_BASE_URL=https://api.deepseek.com
OPENAI_MODEL=deepseek-chat
```

`OPENAI_API_BASE` is still accepted for compatibility with older docs, but
`OPENAI_BASE_URL` should be preferred for new deployments because it matches the
OpenAI SDK naming.
