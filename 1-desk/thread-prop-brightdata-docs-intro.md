### 10.11 La documentación de producto: la quinta unidad de cobro, la API única y la documentación para agentes

La §10 construyó el coste de red de Bright Data sobre la página de precios. Esta captura es la otra cara del mismo proveedor —**la documentación de producto** (`docs.brightdata.com/introduction`)— y aporta tres cosas que la tabla de coste por insumo de la §7 no tenía: **una quinta unidad de cobro**, **una superficie de API unificada** y **un producto pensado para que lo consuman agentes**.

**Lo primero, y lo que rompe la tabla: el crédito.** La portada declara **"5,000 free credits per month, no credit card required"** y el titular **"Scrape any site, buy ready-made datasets. Thousands of pre-built scrapers, one API key."** ([[2026-1026-brightdata-free-tier-de-5000-creditos-sin-tarjeta]]). El **crédito** es una unidad distinta del $/GB, del $/IP y del $/captcha, y en esta página **no tiene conversión publicada**: ni crédito→dólar, ni crédito→GB, ni crédito→request, ni qué consume un crédito ([[2026-1026-brightdata-creditos-como-unidad-sin-conversion-publicada]]). Con eso, la §7 pasa de cuatro unidades a **cinco**, y la quinta es la única que **no se puede cotizar**. El hueco, además, tiene forma concreta: el mismo proveedor cobra el proxy en $/GB y en $/IP, y el producto de datos en créditos, **sin publicar el puente** — de modo que la unidad pública del proveedor es un **crédito sin precio** y la unidad comparable con el resto del corpus es un **$/GB que solo aplica a la red**. La captura de free tier del mismo día (atomizada en paralelo) sí publica el puente —1 crédito por request, 5 por MB en Browser API, valor declarado de unos $7,50— y **el pool de 5.000 créditos excluye los proxies**, de modo que la conclusión que esta sección deja abierta es: **la capa de red del vault no se puede probar gratis, aunque la capa de datos sí** ([[2026-1026-brightdata-proxies-excluidos-con-2-dolares-de-prueba-y-5-de-bonus]]).

**Lo segundo: la API es una sola, y eso es una decisión de arquitectura que el vault tiene que notar.** La autenticación es un único encabezado —`Authorization: Bearer <API_KEY>`— **compartido por todos los productos** ([[2026-1026-brightdata-una-sola-api-key-para-todos-los-productos]]), y el scraping no usa un endpoint por scraper: usa **uno solo**, `POST https://api.brightdata.com/datasets/v3/scrape?dataset_id=<id>&format=json`, y lo que cambia es el `dataset_id` y la URL de entrada ([[2026-1026-brightdata-endpoint-unico-datasets-v3-con-dataset-id]]). Es decir, el catálogo del proveedor —miles de scrapers pre-construidos— **no se expone como miles de endpoints sino como un parámetro**. Consecuencia para el vault: **la superficie de integración es pequeña y el catálogo es grande**, lo que invierte el riesgo habitual de adoptar un proveedor de scraping. El riesgo deja de ser "aprender diez APIs" y pasa a ser "depender de que el `dataset_id` que necesito exista, siga existiendo y devuelva el mismo esquema" —**un riesgo de catálogo, no de API**, que es justo el que la §7 ya no miraba.

**Lo tercero: la documentación se publica para agentes, y eso es una señal de mercado.** Hay un bloque **"You're an agent? Start here"**, un índice **`/llms.txt`** —*"the complete documentation index"*, con la instrucción *"Use this file to discover all available pages before exploring further"* ([[2026-1026-brightdata-llms-txt-como-indice-de-documentacion-para-agentes]])— y un **servidor MCP** con **un solo comando por cliente**: Claude Code, Cursor, Codex CLI y el propio Bright Data CLI ([[2026-1026-brightdata-mcp-un-solo-comando-por-cliente-de-agente]]). El vault ya tenía el MCP como **superficie de ataque** ([[2026-1023-ai-security-tools-mcp-como-superficie-de-ataque]]) y el giro de 2Captcha a infraestructura de acceso para agentes ([[2026-1024-2captcha-giro-hacia-scraping-y-mcp-para-agentes]]); aquí aparece **el segundo proveedor de elusión que publica MCP**, y además publica **su propia documentación en formato para agentes**. El dato relevante para el thread no es la seguridad del MCP sino que **el acceso a datos de terceros se está diseñando como interfaz para agentes, no como API para personas**: la documentación para agentes es ya un estándar de facto entre proveedores ([[2026-1024-dataimpulse-uso-de-ips-en-agentes-y-visibilidad-en-ia]]).

**Y el cuarto bloque, que es un mercado que el thread todavía no tenía: el producto listo para comprar.** La sección "Data extraction" ofrece **SERP API, Web Scraper API, Scraper Studio y Browser API** —Browser API como *"Remote browsers for automation"*, es decir, la huella y la navegación externalizadas ([[2026-1026-brightdata-browser-api-navegadores-remotos-para-automatizar]])— y además un **Dataset Marketplace** con **"Ready-made datasets, 250+ domains"** ([[2026-1026-brightdata-marketplace-de-datasets-con-250-dominios]]), **Business Search** para *"Find people and companies by criteria"* ([[2026-1026-brightdata-business-search-personas-y-empresas-por-criterio]]), y **Media Data API** (*"Video, audio and captions at scale"*) y **Web Archive** (*"Cached web page snapshots"*) ([[2026-1026-brightdata-media-data-y-web-archive-para-entrenamiento-de-ia]]). El titular de la home lo dice sin rodeos: **"Scrape any site, buy ready-made datasets"**. Es decir, el proveedor que tenía el peor contrato de red del corpus **vende también el dato ya scraped**, y con él dos capas de servicio: **Scraper Studio** (cliente define, proveedor hospeda) y **Managed services** (*"Done-for-you data collection"*), cuyo precio está **fuera de la captura** ([[2026-1026-brightdata-capa-de-servicio-encima-de-la-api]]). El thread midió en la §7 que el captcha puede reabsorberse en un recargo del $/GB; esta captura añade que **el scraping entero puede reabsorberse en un precio por proyecto**, y ese precio no está publicado.

**La lectura que cierra la sección.** La §10 concluyó que el problema de Bright Data es el **contrato** —$499 de suelo, KYC para el pool bueno, cierre al 100 % del saldo—. Esta captura muestra que **la documentación de producto no es un subconjunto del problema**: es la capa donde el proveedor **vende la ausencia de fricción**. Un endpoint único, una API key, un MCP por cliente, un índice `llms.txt` y 5.000 créditos sin tarjeta. Todo eso describe una **integración de horas**, y el contrato de $499 describe una **decisión de meses**. El vault ya tenía esto medido en DataImpulse, donde el prepago sin suscripción es la ventaja; aquí la ventaja es **de integración**, y el coste es **de compromiso**.

## INSERTAR en "## 9. Fricciones para juicio humano" — nuevas fricciones numeradas 48–51

48. **Hay tres puertas de coste cero nominal en Bright Data y tres contratos incompatibles, y el thread solo había medido una.** La página de precios ofrece el cupón `RESIGB50` sobre los cuatro planes de tráfico y el *match* del primer depósito "dollar for dollar, up to $500" ([[2026-1024-brightdata-cupon-50-off-y-match-del-primer-deposito]]); la página de free tier ofrece **5.000 créditos mensuales sin tarjeta** ([[2026-1026-brightdata-5000-creditos-gratis-al-mes-para-cuentas-nuevas]]); y la página de documentación abre con **"5,000 free credits per month, no credit card required"** ([[2026-1026-brightdata-free-tier-de-5000-creditos-sin-tarjeta]]). O las tres son la misma oferta descrita en tres sitios, o son tres puertas distintas con requisitos distintos —con depósito, con tarjeta, sin tarjeta— y **el vault no puede tratar "el coste de entrada de Bright Data" como un número único**. La captura de free tier del mismo día **acota una parte**: *"Free credits are consumed first. Promo code discounts apply to any PAYG usage that follows"* —los créditos gratuitos se gastan antes que el cupón y no son acumulables sobre el mismo consumo—, de modo que el cupón y el free tier son **tramos sucesivos del mismo presupuesto**, no dos descuentos encima. Marcado para juicio humano, no auto-resuelto: la captura no publica el valor en dólares de los 5.000 créditos, y sin esa cifra las tres puertas no se pueden comparar en una unidad.

49. **El "cinco tipos de red" de la documentación y los "cuatro tipos de red" del FAQ no se pueden ordenar porque cuentan cosas distintas, y el conteo parece más que multiplicar la superficie comercial que las redes reales.** La docs dice **"Five network types for routing traffic at scale"** y lista Residential, Datacenter, ISP, **Proxy Manager** (*"Open-source proxy routing"*) y **Browser Extension** (*"Proxies in Chrome"*) ([[2026-1026-brightdata-cinco-tipos-de-red-en-docs-contra-cuatro-en-faq]]); el FAQ de la página de precios declara **cuatro redes de IP** —Datacenter, ISP, Residential y **Mobile**— con solo **tres pestañas de precio** ([[2026-1024-brightdata-cuatro-tipos-de-red-y-solo-tres-pestanas-de-precio]]). Las dos últimas entradas de la docs no son redes sino **herramientas de cliente**, y **Mobile falta en la lista de la docs** aunque el FAQ lo trata como red. O el "5" de la docs es un quinto producto de red (imposible: el FAQ es explícito), o es un conteo de **entidades de catálogo** presentadas como redes. El daño no es terminológico: es que **la red móvil sigue sin ser cotizable** y la tabla de coste por insumo conserva su hueco superior, ahora con **dos clasificaciones incompatibles** en la misma marca. Marcado para juicio humano, no auto-resuelto.

50. **La elusión del captcha se reabsorbe en el acceso, pero ahora hay un tercer sitio donde puede esconderse: la Documentation-as-a-Service.** El átomo de Web Unlocker concluyó que el CAPTCHA puede dejar de ser una línea del modelo de coste y pasar a ser un recargo implícito del $/GB ([[2026-1024-brightdata-web-unlocker-resuelve-captcha-y-no-requiere-kyc]]), y la captura de free tier añade que el MCP **consume el mismo pool** porque el servidor MCP corre sobre Web Unlocker ([[2026-1026-brightdata-mcp-consume-el-mismo-pool-de-creditos]]). Pero esta captura añade que el mismo proveedor vende **Scraper Studio** (el cliente define, el proveedor hospeda) y **Managed services** (*"Done-for-you data collection"*), cuyo precio está fuera de la captura ([[2026-1026-brightdata-capa-de-servicio-encima-de-la-api]]). Si el coste se paga por proyecto y no por GB, **la partida de captcha no desaparece: se hace invisible**, porque un precio cerrado por tarea no permite auditar qué parte fue red, qué parte elusión y qué parte trabajo. O la prueba del vault de que "el captcha no es una partida" es válida solo para contratos con unidad abierta, o **necesita el matiz de que solo es auditable en productos con unidad de tráfico publicada**. Marcado para juicio humano, no auto-resuelto.

51. **La documentación y la tabla de precios no son la misma superficie, y el vault tiene que decidir cuál manda cuando discrepan.** La página de precios es la que publica el compromiso de $499, el KYC, el corte por saldo y las dos tablas de $/IP sin etiquetar; la documentación es la que publica el "5.000 créditos sin tarjeta", el "one API key" y los "250+ domains" de datasets listos ([[2026-1026-brightdata-marketplace-de-datasets-con-250-dominios]]). En concreto, **la documentación de Bright Data no repite el KYC**, y el texto "Using Web Unlocker does not require going through the KYC process" sigue siendo solo de la página de precios. O la documentación es un resumen comercial que **omite deliberadamente la fricción**, o es un plano distinto de producto donde el KYC no aplica. Mientras no se resuelva, el vault tiene que citar **la página de precios para el contrato** y **la documentación para la capacidad**, y no al revés: una decisión de compra tomada solo con la documentación subestima el compromiso de capital en dos órdenes de magnitud. Marcado para juicio humano, no auto-resuelto.

**Nota de método — novena tanda de capturas del thread** (atomización del 2026-10-26: documentación de producto de Bright Data). La §10.11 y las fricciones 48–51 proceden de **una única captura**, `sources/2026-10-25-brightdata-docs-intro.md` (página de introducción de `docs.brightdata.com`, 8.543 caracteres de markdown extraído). A diferencia de las ocho tandas anteriores, esta fuente **no es una página de precios**: es **documentación de producto**, de modo que aporta **capacidad y superficie, no cifras de coste**. Toda cifra citada (5.000 créditos, "250+ domains", "400M+ real-user IPs", "one API key", el `dataset_id` de ejemplo) es **claim del proveedor transcrito literalmente**, no medición del vault. Lo medido por el vault en esta tanda son **dos discrepancias internas y una entre capturas**: el **"5" de las redes de la documentación frente al "4" del FAQ de precios** (fricción 49), la **ausencia de conversión del crédito** en esta página frente a su publicación en la página de free tier del mismo día, y el **"no credit card required" de la portada frente al cupón con depósito de la página de precios** (fricción 48). Un apunte de captura que hay que dejar dicho: el frontmatter de la fuente registra `url: https://brightdata.com/faq`, pero **el cuerpo capturado es la página de introducción de `docs.brightdata.com/introduction`** (enlaces internos a `docs.brightdata.com`, botón "Skip to main content" a `docs.brightdata.com/introduction#content-area`, y 545 palabras frente al formato de página de FAQ). Es decir, **la URL del frontmatter y el contenido no coinciden**, y el vault debe citar la fuente por su **contenido** (documentación de producto) y no por la URL registrada, que además es la que ya usaba la tabla de precios. Dos ausencias quedan registradas **como ausencias verificadas sobre la captura**: la documentación **no publica** el precio de Web Unlocker, SERP API, Web Scraper API, Scraper Studio, Browser API, Business Search, Media Data API ni Web Archive; **ni el precio de Managed services** (enlazado a `brightdata.com/pricing/managed-services`, fuera del árbol de documentación); **ni el valor en dólares del crédito**; **ni la caducidad del crédito sobrante**; **ni el desglose de los 250+ dominios** del marketplace. Un apunte de método particular: la captura incluye **comandos de configuración con marcadores de credencial**, que el vault **no transcribe literalmente** en los átomos — el valor de la API key aparece como `[REDACTED]` en todos los casos —, porque la fuente contiene material sensible y la reproducción literal del comando no es necesaria para el claim.

**Apunte para [[el-agregador-de-precios-como-producto]]:** el Dataset Marketplace de Bright Data ofrece **"Ready-made datasets, 250+ domains"** ([[2026-1026-brightdata-marketplace-de-datasets-con-250-dominios]]) y **Business Search** para *"Find people and companies by criteria"* ([[2026-1026-brightdata-business-search-personas-y-empresas-por-criterio]]). Son dos piezas del mismo movimiento que la §8 del agregador ya había detectado en el proveedor de proxies: **la capa de datos crudos que un agregador de precios necesita por debajo de su lógica de frescura está dejando de construirse y empieza a comprarse como catálogo**. Y hay un dato que conecta directamente con la tesis del thread: el proveedor que vende el dato listo **también** publica su propia documentación en `/llms.txt` para agentes ([[2026-1026-brightdata-llms-txt-como-indice-de-documentacion-para-agentes]]), es decir, **la fuente de datos y la documentación de esa fuente son consultables por la misma maquinaria de agente** que consume los datos. Un agregador que construya su propia capa de scraping está, para este proveedor, sustituible por un endpoint.

**Apunte para [[myownclone-platform-architecture]]:** la captura confirma que el scraping del vault tiene una alternativa de producto con **superficie de integración de horas y compromiso de meses**: **un endpoint único** con `dataset_id`, **una API key** para todo el catálogo, **un servidor MCP por cliente de agente** y **5.000 créditos mensuales sin tarjeta** ([[2026-1026-brightdata-endpoint-unico-datasets-v3-con-dataset-id]], [[2026-1026-brightdata-una-sola-api-key-para-todos-los-productos]], [[2026-1026-brightdata-mcp-un-solo-comando-por-cliente-de-agente]]). El pipeline de ingesta del vault ([[2026-1022-myclone-scraping-ingestion-pipeline]]) construye, con `auto-onboard` y `bulk-onboard` incluidos, una capa que este proveedor da por hecha —**pero con el catálogo como riesgo y no la API**—. El corolario operativo para el build-vs-buy del thread: **el coste de integración es bajo y el coste de dependencia (esquemas que cambian, `dataset_id` que aparece y desaparece) es el que hay que cotizar**, y esa cifra no está publicada en ninguna parte de la captura.
