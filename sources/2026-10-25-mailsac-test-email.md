## Frequently Asked Questions

How do I create a test email account?

You don’t need to create one. Choose any address at @mailsac.com, send your test email to it, then open that inbox on mailsac.com or read it with the API.

@mailsac.com inboxes are public, so use made-up data. For test mail that only your team can read, create a free account: it includes an API key and one private address, and paid plans add custom test domains.

Can I use Mailsac for testing?

Yes. Mailsac is built for testing email. QA and development teams use it to check sign-up confirmations, password resets and one-time codes, by hand in the web inbox or from automated tests and CI pipelines through the REST API.

Use public @mailsac.com addresses for made-up test data, and a private address or custom domain for anything sensitive.

What features for teams does mailsac have?

mailsac helps and QA teams wrangle their test inboxes seamlessly.

SSO is supported (users must be added to mailsac first).

You can share email test logins, access the same custom domains, manage team API keys, manage sub-accounts, and delegate management of certain tasks.

Can other people see my email messages?

Email messages are private to your account when using a custom domain or custom private forwarding address.

Sending to any address @mailsac.com works, but it’s public and subject to throttling.

Do I have to create/setup the email address before sending mail?

You can send immediately to any address @mailsac.com or @ your custom domain. No need to create the inbox first.

The API supports checking mail for any address, and will return 200 with an empty array if no mail exists there.

To access custom forwarding features (to web socket, webhook, slack, etc), you must  “reserve” that address first. This is called a custom private forwarding address.

Can I integrate my CI pipeline with mailsac?

Companies large and small rely on mailsac to test email workflows as part of their continuous integration pipeline.

We support teams with high uptime requirements, who have integration email tests running 24/7.

mailsac uses standard open protocols like REST, Web Sockets, and Webhooks to allow you to integrate testing pipelines with any system – Jenkins, GitHub Actions, Selenium, GitLab CI, Bamboo, etc – any is supported, as long as it can access mailsac.com.

Can mailsac be used in a high security environment?

We have many customers in finance, government, scientific research, and the high tech industries.

In these environments we can provide a copy of our Information Assurance Program, security scanning results, and help you complete a Vendor Risk Assessment (VRA). Note: only supported for our Enterprise plan tier.

Does mailsac work with enterprises?

We value our relationships with customer of all sizes. About half of mailsac’s customers are enterprise scale. We interact with enterprises on a daily basis.

Can mailsac take a P.O.?

Purchase order billing is supported on annual Business+ and Enterprise plans.

We recommend a 2-year billing cycle.

Does mailsac have SSO?

Single-sign-on is supported via SAML on the Business, Business+ and Enterprise plans. Users need to be added in mailsac first, by email address.

There’s some typical SAML configuration necessary in your SSO provider, and in mailsac – you have to swap config. We will support you via email (business plans) and on a screenshare (enterprise plans) if you require assistance.

Can AI agents use Mailsac for email testing?

Yes. An agent that can make HTTP requests can use Mailsac’s REST API to list received messages and read their contents. Use a [private address](https://docs.mailsac.com/en/latest/services/private_addresses/private_addresses.html) or [private custom domain](https://docs.mailsac.com/en/latest/services/custom_domains/custom_domains.html) for sensitive test emails. Start with the [REST API quickstart](https://docs.mailsac.com/en/latest/api_examples/getting_started/getting_started.html).
